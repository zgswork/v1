核心问题

01

为什么普通 AI 总是"纸上谈兵"

Agent 与普通 AI 的分水岭

普通 AI 能写代码、能分析数据、能出方案，但有一个根本缺陷——它的一切输出都止于文本。它无法保存文件、无法调用工具、无法读取实时数据。所有"记忆"困在对话上下文里，token 一满就失忆，会话一断就归零。

Agent 与普通 AI 的分水岭，就在于有没有一套外部 API 层。 API 是 AI 的"神经末梢"：AI 通过 HTTP 请求发出指令，API 负责落地执行，并把结果返回给 AI 继续决策。没有这层接口，AI 永远只是聊天框里的顾问；有了这层接口，AI 才能真正动手做事。

本专栏解决的就是如何零成本、无公网 IP、无域名地搭建这套 API 层，让普通 AI 拥有 Agent 级的执行能力。

三大 API 场景

03

文件管理 API：状态持久化与跨会话续接

解决 AI 的"金鱼记忆"

plan.json、checkpoint、缓存数据需要跨会话保存，但普通 AI 平台不开放文件系统。自建文件管理 API 让 AI 拥有真正的外部存储。

API 设计范式

方法路由语义
GET/api/files/{path}读取目录或文件内容
POST/api/files/{path}创建目录 / 上传文件 / 分片上传
PUT/api/files/{path}更新文件（旧版自动备份）
DELETE/api/files/{path}移入回收站（非永久删除）
POST/api/batch/delete批量操作，返回每条独立结果

关键设计细节

  • 资源即 URL：{path} 直接映射存储路径，符合 REST 直觉
  • 动作即 HTTP 方法：用 GET/POST/PUT/DELETE 表达意图，而非在 URL 里写动词
  • 分片上传：通过 X-Chunk-Index、X-Chunk-Total、X-Upload-Id 三个 Header 实现大文件断点续传
  • 路径沙箱：safe_path() 用 os.path.realpath() 做路径解析，防止目录遍历攻击
  • 多方式认证：支持 Authorization: Bearer、Cookie、URL 查询参数，适配不同调用场景

04

MCP 转接 API：打通工具生态

让普通 AI 也能连接外部工具

普通 AI 不支持 MCP（Model Context Protocol），无法连接文件系统、数据库、浏览器等外部工具。通过自建 API 作为 MCP 转接层，AI 只需会发 HTTP 请求即可调用任意 MCP 工具。

架构设计

外部工具

SQLite / 浏览器 / Shell

MCP Server

本地协议层

Flask 转接层

HTTP REST 封装

AI 用 requests 调用
普通 AI 客户端

Kimi / Claude / ChatGPT

转接层路由

  • GET /api/mcp/tools — 列出当前可用的 MCP 工具清单
  • POST /api/mcp/call — 调用指定工具，参数通过 JSON body 传递

实现步骤

  1. 在 Termux 中安装 MCP SDK（Node.js 或 Python 版本）
  2. 启动本地 MCP Server（如文件系统 MCP、SQLite MCP）
  3. Flask 转接层负责：接收 AI 的 HTTP 请求 → 翻译为 MCP 调用 → 返回结构化结果
# AI 调用示例
# 1. 查询可用工具
tools = requests.get(f"{BASE}/api/mcp/tools?token={TOKEN}").json()

# 2. 调用文件系统工具读取 plan.json
result = requests.post(f"{BASE}/api/mcp/call?token={TOKEN}", json={
    "tool": "read_file",
    "params": {"path": "/storage/emulated/0/plan.json"}
}).json()
核心洞察：AI 不需要原生支持 MCP，它只需要会发 HTTP 请求。转接层负责协议翻译。
05

GitHub 代理 API：实时知识库

让 AI 读取训练截止日期之后的世界

AI 训练数据有截止日期，无法获取最新开源代码和最佳实践。通过自建代理 API，AI 可以实时读取 GitHub 上的任意项目源码。

路径 A：直接代理

Flask 服务提供代理路由，AI 通过你的 API 间接访问 GitHub，无需处理 GitHub API 的 base64 编码和速率限制细节。

路径 B：带缓存的代理

GitHub API 有速率限制（未认证 60 次/小时）。在 Flask 服务里加本地缓存层：首次请求调用 GitHub API 并保存到本地，后续请求直接读缓存。

AI 使用策略

  • 先读 README 和目录结构了解项目架构
  • 再按需深入 2~3 个具体文件
  • 避免一次性塞满上下文窗口
# AI 通过你的代理 API 读取开源代码
code = requests.get(
    f"{BASE}/api/github/read?owner=facebook&repo=react&path=packages/react/src/ReactHooks.js&token={TOKEN}"
).text

API 设计通用原则

06

安全、接口、部署三件套

无论业务是什么，骨架不变

安全三件套

  • 输入校验：所有路径、参数做白名单校验，防注入和目录遍历
  • 身份认证：多方式支持（Bearer Token / Cookie / URL Param），Token 随机生成
  • 操作兜底：删除不是真删除，移入回收站；更新先备份旧版

接口设计规范

  • 统一响应格式：{ok: bool, data?: any, error?: string}，AI 容易解析
  • 批量接口：复杂操作提供 /api/batch/*，接收 JSON 数组，返回每条独立结果
  • 健康检查：必须有 /api/status，部署脚本先验证本地健康再穿透公网
  • 操作日志：所有写操作记录到日志文件，便于审计和回滚

部署规范

  • 一键部署：提供 setup.sh，环境检测 → 依赖安装 → 配置生成 → 服务启动 → 穿透公网，全程自动化
  • 停止脚本：提供 stop.sh 清理进程，避免僵尸服务
  • 本地优先验证：curl http://127.0.0.1:8082/api/status 通过后再启动 Cloudflare Tunnel

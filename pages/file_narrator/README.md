### 声音模板实现原理（重要）

浏览器 Web Speech API 没有真正的"变声"引擎。模板通过两层手段实现：
1. **优先挑选系统中性别匹配的中文语音**（如 Win11 的 Microsoft Xiaoxiao=女声、Yunyang=男声）；
2. **调整 pitch / rate**（男播音=男声+略低音调；女播音=女声+标准语速；萝莉音=女声+高音调+稍快；大叔音=男声+低音调+慢速）。

因此不同电脑/手机上效果取决于系统已安装的语音包；Windows 可在
`设置 → 时间和语言 → 语音` 中添加中文语音以获得更好效果。

## 四、如何维护解说数据（js/narration_data.js）

```js
const NARRATION_DATA = {
  defaultPdf: "steel-drawing",   // 默认选中的条目（取 pdfs[].id，留空则第 1 个）
  defaultTemplate: "male",       // 默认声音模板：male 男播音 / female 女播音 / loli / uncle
  defaultVoiceOn: true,          // V0.5.0：是否默认勾选「语音说明」（false 则默认关闭）

  pdfs: [
    {
      id: "steel-drawing",                     // 唯一标识
      name: "钢结构图（真实施工图示例）",        // ★ 下拉列表里显示的名称
      type: "pdf",                             // ★ 文件格式（可省略，按扩展名 + 签名自动判定）
      url: "file/steel-drawing-sample.pdf",  // 文件路径
      basePoint: { x: 0.5, y: 0.5 },           // ★ 该条目的标准基点（页面比例 0~1）
      pages: [                                 // 下标 = 页码 - 1
        { hotspots: [ { x: 0.373, y: 0.330, title: "标题", text: "解说…" } ] },
        // …每页一项；某页不需要触点就写 { hotspots: [] } 或省略该项
      ]
    },
    { id: "demo", name: "演示文档（内置示例）", url: "file/demo.pdf", basePoint: {...}, pages: [...] }
  ]
};
```

`type` 取值（**V0.5.0 起共 9 种；省略时按扩展名自动判定，判定后还会按文件签名复核**）：

| type | 适用扩展名 | 处理方式 |
|---|---|---|
| `"pdf"` | pdf | PDF.js 渲染，页数取自文件本身 |
| `"image"` | png / jpg / jpeg / gif / webp / bmp / svg | 直接用 `<img>` 显示，**每页用 `src` 指定图片** |
| `"text"` | txt / md / csv / log / ini / json … | 自动排版分页（A4 比例 760×1075），支持 `\f` 或单独一行 `---` 显式分页 |
| `"docx"` | docx / docm | 解包读 `word/document.xml`，识别标题样式，按分页符分页 |
| `"doc"` | doc | 旧版二进制，尽力提取文字（不足时给提示页，不报错） |
| `"pptx"` | pptx / pptm | 一张幻灯片 = 一页，页数由文件内幻灯片数决定 |
| `"ppt"` | ppt | 旧版二进制，同上尽力提取 |
| `"dxf"` | dxf | 解析 `ENTITIES` / `BLOCKS` 后绘制；支持 `LINE`/`LWPOLYLINE`/`CIRCLE`/`ARC`/`ELLIPSE`/`TEXT`/`MTEXT`/`POINT`/`INSERT`（块参照展开） |
| `"dwg"` | dwg | 浏览器无法解析二进制，渲染一页**转换指引**；若该 `.dwg` 实际是文本 DXF 则自动按 DXF 解析 |

- **多条**：直接往 `pdfs` 数组里加对象即可（各格式都行），下拉列表自动出现该条目（顺序 = 数组顺序）。
- **标准基点**：每个条目可各自设定；`{x:0.5, y:0.5}` 即页面中心。所有页的触点都基于同一基点定位，换图版式只需改这一处。
- **触点位置** = 基点 + 偏移，均为页面比例（0~1），自动换算像素，无需关心分辨率；越界会自动钳制在页面 3%~97% 区间。
- **新增**：向某页 `hotspots` 数组加一个对象；**删减**：删除对应对象即可；某页无热点则该页正常翻页无触点。修改后刷新浏览器即生效。
- **定位技巧**：PDF / 图片用阅读器或图像工具量取目标位置的横向、纵向百分比，减去基点即为偏移量。
  文本 / Word 页的排版参数集中在 `index.html` 内联格式适配层的 `TEXT_LAYOUT`（760×1075，左边距 56 / 760 ≈ 7.4%），
  幻灯片是 `SLIDE_LAYOUT`，CAD 图是 `CAD_LAYOUT`。
- **触点可以放心放在边沿附近**（页脚、右下角等）：V0.5.1 起弹窗会自动平移 / 翻转回内容区之内，
  不会被裁断，不需要为了避开裁切而把触点往中间挪。

### 图片条目（V0.4.0：图片也能逐页解说）

图片与 PDF 共用同一套结构，只是把 `type` 改为 `"image"`，并用**每页的 `src`** 代替条目的 `url`：

```js
{
  id: "photo", type: "image", name: "现场照片", basePoint: { x: 0.5, y: 0.5 },
  pages: [
    { src: "file/photo-1.jpg", hotspots: [ { x: -0.2, y: 0.1, title: "屏体", text: "…" } ] },
    { src: "file/photo-2.jpg", hotspots: [] }
  ]
}
```

- 页码 = 图片张数；翻页即换图，格式可用 png / jpg / webp 等浏览器支持的任意类型；
- 触点位置算法与 PDF **完全相同**（比例坐标 = 目标位置比例 − `basePoint`），
  建议 `basePoint` 取图片中心 `{x:0.5, y:0.5}`，量取到百分比后直接相减即可；
- 图片按容器宽度自适应缩放，因此手机与电脑上的触点相对位置一致（不需要像 PDF 那样重绘）；
- 图片缺失 / 格式不支持时与 PDF 加载失败表现一致：显示错误面板 + 按钮与复选框全部不可用；
- 解说语音同样适用（`file/voice/<id>/p<页>-<序>.mp3`），改完文案双击 `tools/gen_voice_oneclick.pyw` 即可。

### TXT / Word / PPT / DXF / DWG 条目（V0.5.0：零依赖解析）

这五种格式都由 `index.html` 内联的格式适配层在浏览器里**纯 JavaScript 解析**（不引用任何第三方库 / CDN），
统一输出成同一种画布模型 `CanvasDoc = { kind, label, note, pages: [{ w, h, draw(ctx) }] }`，
再交给主逻辑（同为 `index.html` 内联段）已有的画布渲染流程绘制 —— 因此**触点定位、弹窗、朗读、自动巡讲、字幕条
与 PDF / 图片完全共用一套逻辑**，界面表现一致。

结构上与 PDF 条目完全相同，只需要加一个 `type`（也可以省略，程序按扩展名 + 文件签名自动判定）：

```js
{ id: "notes-txt",  type: "text",  name: "施工要点（TXT）", url: "file/demo-notes.txt",  basePoint: { x: 0.5, y: 0.5 }, pages: [ … ] }
{ id: "report-docx",type: "docx",  name: "施工方案（Word）", url: "file/demo-report.docx", basePoint: { x: 0.5, y: 0.5 }, pages: [ … ] }
{ id: "slides-pptx",type: "pptx",  name: "技术交底（PPT）",  url: "file/demo-slides.pptx", basePoint: { x: 0.5, y: 0.5 }, pages: [ … ] }
{ id: "plan-dxf",   type: "dxf",   name: "钢结构正立面（DXF）", url: "file/demo-plan.dxf",  basePoint: { x: 0.5, y: 0.5 }, pages: [ … ] }
{ id: "plan-dwg",   type: "dwg",   name: "钢结构图（DWG）",   url: "file/demo-plan.dwg",    basePoint: { x: 0.5, y: 0.5 }, pages: [ … ] }
```

几点差异值得留意：

- **页数来源不同**：PDF 页数取自文件本身；**文本 / Word 是自动排版分页**（页数取决于文案长度与 `TEXT_LAYOUT` 参数）；
  **PPT 一张幻灯片 = 一页**；**DXF / DWG 默认整图 1 页**。因此新增条目时，`pages` 数组要和你实际看到的分页一致
  （多出来的会正常翻页但无触点，少写了则后面的页没有触点数据）。
- **DXF 做局部放大**：某一页里写 `view: { x0, y0, x1, y1 }`（图形坐标）即可只显示该范围，
  用「第 1 页总图 + 第 2 页局部放大」的方式讲解细节。
- **DWG 要转换**：DWG 是 AutoCAD / ZWCAD 专有二进制，浏览器没有解析器。检测到真 DWG 时页面会渲染
  一页**转换指引**（三种处理办法：CAD 里 `DXFOUT` 另存 DXF / 另存 PDF / 截图输出 PNG）。
  若你把 `.dwg` 换成文本型 DXF 的真实内容，程序会按签名自动识别并按 DXF 正常画图。
- **旧版 doc / ppt**：二进制格式没有公开的完整规范，`loaders.js` 只做**尽力提取**（能取到多少算多少），
  取不到就显示提示页而非报错。要保证还原度，建议在 Office / WPS 里另存为新版 `docx` / `pptx`。
- **素材生成**：示例素材由 `tools/make_demo_docs.py` 用**纯 Python 标准库**生成（`zipfile` 手写最小
  Office 包），无需任何第三方库；改了示例文案重跑该脚本即可。

## 五、更换 / 新增 PDF、图片与其它格式

**新增 PDF**：

1. 把 PDF 放入 `file/`（建议用英文文件名，避免 URL 编码问题）；
2. 在 `narration_data.js` 的 `pdfs` 数组里新增一个条目（`id` / `name` / `type: "pdf"` / `url` / `basePoint` / `pages`）；
3. 刷新页面，用下拉列表选择即可。

**新增图片（V0.4.0）**：

1. 把图片（png / jpg / webp 等浏览器支持的格式）放入 `file/`；
2. 在 `pdfs` 数组里新增条目，把 `type` 设为 `"image"`，并去掉 `url`、改用每页 `src`：

```js
{
  id: "photo", type: "image", name: "现场照片", basePoint: { x: 0.5, y: 0.5 },
  pages: [
    { src: "file/photo-1.jpg", hotspots: [ { x: -0.2, y: 0.1, title: "屏体", text: "…" } ] },
    { src: "file/photo-2.jpg", hotspots: [ { x: 0.1, y: -0.05, title: "背杆", text: "…" } ] }
  ]
}
```

3. 触点偏移的算法与 PDF 相同（比例坐标 = 比例位置 − `basePoint`），可用图像编辑工具或
   看图软件量取目标位置的百分比；本项目示例图片的偏移由
   `tools/make_demo_images.py` 生成时直接打印。
4. 图片的解说音频同样由一键脚本生成（`file/voice/<id>/p<页>-<序>.mp3`），改完文案双击
   `gen_voice_oneclick.pyw` 即可。

> 小技巧：图片条目同样支持多页（一个条目挂多张图，翻页切换），也支持把同一张图
> 拆成「整图 / 局部放大」两页来讲，配合触点解说效果更好。

**新增 TXT / Word / PPT / DXF / DWG（V0.5.0）**：

1. 把文件放进 `file/`（**建议用英文文件名**，避免 URL 编码问题）；
2. 在 `pdfs` 数组里新增条目，`type` 按上表写（也可省略让程序自动判定），其余字段与 PDF 相同：

```js
{ id: "plan-dxf", type: "dxf", name: "钢结构正立面（DXF）",
  url: "file/demo-plan.dxf", basePoint: { x: 0.5, y: 0.5 },
  pages: [ { hotspots: [ { x: 0.02, y: 0.04, title: "屏体轮廓", text: "…" } ] } ] }
```

3. 刷新页面，用下拉列表选择；**先看清实际分页**（文本 / Word 是自动排版分页、PPT 按幻灯片张数、
   DXF / DWG 默认 1 页），再据此把触点写进对应的 `pages` 项；
4. 解说音频同样由一键脚本生成，改完文案双击 `tools/gen_voice_oneclick.pyw` 即可。

> 小技巧：DXF 想讲细节，就在某一页里加 `view: { x0, y0, x1, y1 }`（图形坐标）做主图 / 局部放大两页。

## 七、故障排查

### 页面出现红色"文件加载失败或无法显示…"提示

**V0.2.1 起该提示框下方会直接列出具体失败原因**（例如 `HTTP 404`、`方案①超时`、`PDF 引擎未加载`、
`渲染第 1 页失败`、`格式适配层未加载`），这是手机端唯一可用的"控制台"。常见情况与处理：

| 现象 / 提示内容 | 原因 | 处理 |
|---|---|---|
| 提示框常驻、下方**无任何原因文字** | **V0.2.0 及更早版本的 CSS 缺陷**：`.load-error{display:flex}` 覆盖了 `hidden` 属性，遮罩永远可见，与文件实际加载无关 | 升级到 V0.2.1 后**强制刷新清缓存**（电脑 Ctrl+F5；手机下拉刷新或清浏览器缓存） |
| `HTTP 404` | `narration_data.js` 里的 `url` 与实际文件名不一致，或文件没放进 `file/` | 核对 `url`、文件名与大小写 |
| `方案①失败` 后自动继续 | 该浏览器不支持 Worker / 流式读取，属正常降级过程（仅 PDF 条目） | 无需处理，程序会自动尝试后续方案 |
| 全部方案失败并列出 4~5 条原因 | 移动端内核限制或文件损坏 | 把页面上的原因**截图反馈**；可先用下拉框切换另一个文件验证 |
| `格式适配层未加载` | `index.html` 内联格式适配层段被误删/改动出错 | 核对内联段完整（段首有「格式适配层」分隔注释），并强制刷新 |
| 选了 DWG 却只看到一页文字说明 | DWG 是专有二进制，浏览器无法解析图形本体 | **属预期行为**：按提示页的三种办法转成 DXF / PDF / 图片后替换 `url` |
| 旧版 `.doc` / `.ppt` 只显示出很少文字 | 二进制格式无完整公开规范，只能尽力提取 | 在 Office / WPS 里另存为 `docx` / `pptx` 后替换 |
| 直接双击 `index.html` 打开 | Chrome 禁止 `file://` 页面读取本地文件 | 改用 `python -m http.server` 或工作台 http 方式打开 |

### V0.2.1 的加载降级顺序（出问题时看这段；仅 PDF 条目）

1. **方案①** `getDocument({url})` —— URL 直连，支持分块按需加载（桌面与主流手机浏览器走这里）；
2. **方案②** 先 `fetch` 整包 → `getDocument({data})`，并关闭 `disableStream / disableAutoFetch / useWorkerFetch`；
3. **方案③** 在方案②基础上加 `isEvalSupported:false`（部分移动内核禁止动态求值）；
4. **方案④** 把 `js/lib/pdf.worker.min.js` 当普通脚本载入主线程后再解析 —— **完全不使用 Worker**，移动端兜底。

每级超时 20 秒（主逻辑内联段顶部常量 `LOAD_TIMEOUT`）。任一方案成功即正常显示；全部失败才报错。
**V0.5.0 的新格式（TXT / Word / PPT / DXF / DWG）不经过 PDF.js**，本地解析失败会直接给出原因（如
`格式适配层未加载`、`解析失败`），不会走这套四级降级。

## 八、手机上没有语音声音怎么办

先说结论：**语音是浏览器调用手机系统自带的 TTS 引擎合成的**，页面本身不带音频文件。
V0.2.2 已把三种“代码层可解决”的原因修掉（iOS 首次手势限制、utterance 被 GC、无引擎静默失败），
剩下的是系统 / 浏览器环境问题。页面工具栏下方会出现一条浅黄色提示条直接说明属于哪种情况
（12 秒后自动消失），按它的提示处理即可。

| 现象 | 原因 | 处理 |
|---|---|---|
| 提示条：“当前浏览器没有可用的语音引擎” | 浏览器不支持朗读，或系统未安装 TTS 引擎 | **微信、QQ 等内置浏览器通常不支持语音朗读**，请改用系统浏览器（Chrome / 夸克 / Edge / Safari）；安卓进「设置 → 无障碍 → 文字转语音」安装并启用中文语音 |
| 提示条：“系统里没有找到中文语音包” | 有引擎但没有中文发音人 | 在手机的「文字转语音」设置里安装中文语音包 |
| 提示条：“语音引擎没有发出声音” | 引擎存在但没出声 | iPhone 请**拨掉侧边静音开关**（该开关会让网页语音一起静音）并调高媒体音量；安卓检查媒体音量与“静音/勿扰”模式 |
| 没有提示条但也无声 | 可能没开启语音说明 | 勾选工具栏的「🔊 语音说明」；或直接点「▶ 自动翻页」，巡讲会自动勾选语音 |
| 电脑有声、手机无声 | iOS 的首次发声必须在用户手势内（V0.2.2 已修） | 在手机页面上**先随便点一下屏幕**（点触点或按钮）完成解锁，之后再触发解说 |

> 排查顺序：先看提示条 → 再看系统 TTS 设置 → 最后换成系统浏览器。
> 另外提醒：iPhone 的侧边静音开关、媒体音量为 0、开启“勿扰模式”都会导致网页语音无声，这与代码无关。

**V0.2.3 起**：一旦判定当前浏览器无法发音（无引擎 / 无中文语音包 / 重发一次仍发不出声），
页面在显示提示的同时会**自动取消「语音说明」勾选**（巡讲也会一并停止，提示条末尾会说明原因）。
此时解说文字与弹窗仍正常显示，手动悬停触点依然能看到内容；
若之后处理好了系统语音（装了中文语音包 / 拨掉静音开关 / 换成系统浏览器），
**重新勾选「🔊 语音说明」**即可恢复朗读。

**V0.3.0 起**：项目已内置**离线语音文件**（`file/voice/`）。上述情况不再直接关闭语音，
而是自动改播预生成的音频文件（详见下一章）—— 只有音频文件也播不出来时，才回到
“取消勾选”的降级行为。

## 九、离线语音文件（浏览器不能朗读时改播音频）

**为什么**：网页语音是浏览器调用**手机系统自带的 TTS 引擎**现场合成的，微信/QQ 内置浏览器、
部分安卓机、较旧版 iOS 上根本没有可用的中文引擎，网页无法凭代码补。
因此把每条解说**预先合成为 mp3**存在本地：浏览器能朗读时用实时朗读（可切声音模板），
发不出声时**直接播放音频文件**，音质更稳定、完全离线。

**工作方式**（主逻辑内联段）：

| 场景 | 行为 |
|---|---|
| 浏览器能朗读（电脑 Chrome/Edge、系统浏览器） | 仍用 Web Speech 实时朗读，四种声音模板可选 |
| 判定浏览器发不出声（无引擎 / 无中文语音包 / 重发一次仍无反应） | **自动改播音频文件**，提示条告知；**声音模板下拉置灰禁用**（音频音色固定） |
| 音频文件也播不出来（缺失 / 浏览器拦截自动播放） | 提示具体原因，并自动取消「语音说明」勾选（V0.2.3 行为） |

> 音频模式下巡讲完全正常：一条播完（`ended` 事件）→ 2 秒 → 下一条 → 页尾自动翻页。

**音频文件命名**：`file/voice/<pdfId>/p<页码>-<触点序号>.mp3`（均从 1 起），
与 `js/narration_data.js` 中 `pdfs[].id` 和 `pages[].hotspots[]` 的顺序对应。

**改了文案 / 增删触点后，必须重新生成音频**（否则音频与页面文字不一致）：

### 方式 A（推荐）：双击 `tools/gen_voice_oneclick.pyw` 一键完成

Windows 下 `.pyw` 不弹黑色控制台窗口，所有日志显示在窗口里。它一次做完：

1. 读取 `js/narration_data.js` 提取每个触点的文案（纯 Python 解析，**不要求装 Node**）；
2. 与 `file/voice/` 现状 + 上次清单的**文案指纹**逐条比对，算出「缺的 / 文案改过的」；
3. 只合成这些条目，仍按 `file/voice/<pdfId>/p<页>-<序>.mp3` 规则落盘。

| 界面按钮 | 作用 |
|---|---|
| 🚀 一键生成 | 智能增量：只做「文件缺失」与「文案已改动」的条目 |
| ♻ 全部重新生成 | 忽略增量全部重做（换音色 / 语速后用） |
| 📋 仅导出清单 | 只刷新 `tools/voice_manifest.json`，不合成音频 |
| 🔧 安装/修复 edge-tts | 给本机 Python 安装 edge-tts（只需一次，需联网） |
| 📂 打开音频目录 | 打开 `file/voice` |
| 🛑 停止 | 中途终止（已生成的音频保留，再点一键生成即可续做） |

命令行等价用法（排查问题用，日志与界面完全一致，并写入 `tools/voice_build.log`）：

```bash
python tools/gen_voice_oneclick.pyw --auto              # 智能增量生成
python tools/gen_voice_oneclick.pyw --auto --force      # 全部重新生成
python tools/gen_voice_oneclick.pyw --auto --dry-run    # 只分析，不生成（演练）
python tools/gen_voice_oneclick.pyw --auto --only demo  # 只做某个 PDF（pdfs[].id）
python gen_voice_oneclick.pyw --check             # 检查本机 Python / edge-tts 环境
python gen_voice_oneclick.pyw --list              # 列出全部条目与文案指纹
```

> 找不到 edge-tts 时，脚本会自动在多个 Python 里挑一个装了的（含 Python 虚拟环境）；
> 一个都没有时，点界面上的「🔧 安装/修复 edge-tts」即可。
>
> 若双击 `.pyw` 毫无反应（说明该机器上 `.pyw` 没关联到 Python），
> 双击同目录的 **`gen_voice_oneclick.bat`** 效果相同。

### 方式 B：手动两步

```bash
# 1) 导出文案清单（读 js/narration_data.js；Node 版与 Python 版输出完全一致，任选其一）
python tools/narration_manifest.py       # 纯 Python，无需 Node

# 2) 批量合成 mp3（需 pip install edge-tts；生成时联网，生成后可完全离线）
python tools/gen_voice_files.py             # 增量生成（已存在的跳过）
python tools/gen_voice_files.py --force     # 全部重新生成
python tools/gen_voice_files.py --list      # 只看将生成哪些文件
python tools/gen_voice_files.py --only demo # 只生成某个 PDF
```

> 一键脚本内部就是方式 B，区别是多了「文案指纹比对」，因此只重做改动的那几条，
> 并在写清单前把变动条目的旧音频清掉，避免音文不一致。

**换音色**：改 `--voice`（如 `zh-CN-YunjianNeural` / `zh-CN-XiaoxiaoNeural`），并同步修改
`js/narration_data.js` 的 `offlineVoice.voiceLabel` 便于记录。音色一览：
`python -m edge_tts --list-voices | findstr zh-CN`。

**关闭兑底**：把 `js/narration_data.js` 的 `offlineVoice.enabled` 设为 `false`，
则浏览器不能朗读时只显示文字解说（V0.2.3 行为）。

> 当前音频音色：`zh-CN-YunxiNeural`（云希·中文男声），语速 `-5%`，共 58 条 / 约 5.31 MB
> （PDF 条目 23 条 + 图片 12 条 + TXT 6 条 + Word 6 条 + PPT 6 条 + DXF 3 条 + DWG 2 条）。

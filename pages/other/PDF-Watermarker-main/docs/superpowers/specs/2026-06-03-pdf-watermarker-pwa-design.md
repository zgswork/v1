# PDF 加水印工具（PWA）设计文档

- 日期：2026-06-03
- 状态：已通过设计评审，待写实现计划
- 参考：`Doc/企业微信截图_17804636849887.png`（功能参考截图）

## 1. 背景与目标

参考一款现有的"PDF 加水印"线上工具，做一个**功能更强、体验更好的同类工具**。
当前项目仅有一张 UI 参考截图，无任何代码，从零搭建。

核心目标：
1. **跨平台、可安装**：以 PWA 形式交付，浏览器即开即用，也可"安装"到 Windows / macOS 桌面，带图标、可离线。
2. **水印能力强**：文字水印 + 图片水印，平铺/单点、旋转、颜色、大小、透明度、字体、页码范围。
3. **交互体验好**：实时预览、所见即所得。

隐私：所有处理**全部在客户端**完成，PDF 不上传服务器，适合医院/政务等敏感文档。

## 2. 技术选型

**React + pdf-lib + pdf.js + fontkit，以 PWA 交付（纯客户端，无后端）。**

决定性理由：
1. **授权干净**：pdf-lib(MIT)、pdf.js(Apache-2.0) 均为宽松许可，将来闭源/商业发行无需付费。刻意避开 iText / PyMuPDF 等 AGPL 授权。
2. **跨平台一致**：基于浏览器内核渲染，配合 PWA 可安装、可离线，省去 Electron 的代码签名/公证与上百 MB 包体。
3. **生态成熟**：「pdf-lib 加水印 + pdf.js 预览 + fontkit 嵌中文字体」是被广泛验证的组合，中文/图片水印都可靠，维护成本低。

被否决的方案：
- Electron：能力够但包大、需签名公证；PWA 已满足"可安装桌面应用"诉求。
- Tauri / Wails：两端系统 WebView 渲染可能有差异，对预览重度场景是隐患。
- PySide6 + PyMuPDF：PDF 能力最强，但 PyMuPDF 为 AGPL，商业闭源需购买 Artifex 授权，出局。

**架构兼容性**：水印引擎为纯 TS、与 UI 解耦，将来若需真正的原生桌面 App，可用 Electron 薄包一层，核心代码几乎不改。

## 3. MVP 范围

**包含：**
- 单个 PDF 加水印
- 文字水印 + 图片水印（上传 logo）
- 平铺 / 单点定位（九宫格 9 锚点）、旋转角度、平铺间距
- 样式：颜色、大小、透明度、字体（黑体 / 宋体）
- 文档页码范围（起止页）
- 实时预览（所见即所得）
- PWA：可安装、离线、纯客户端不上传
- 水印模板保存 / 复用（本地）

**明确不做（留后续版本，架构上不挡路）：**
- 变量水印（姓名/部门/时间/页码等动态变量）
- 批量多文件
- 防篡改 / 暗水印

## 4. 整体架构（纯客户端 PWA）

```
┌──────────────────────────────────────────────┐
│  浏览器 / 已安装的 PWA                          │
│                                                │
│  React UI 层                                   │
│   · 文件列表 + 水印设置面板 + 实时预览          │
│                                                │
│  水印引擎 (纯 TS, 跑在 Web Worker, 不卡界面)    │
│   · pdf-lib 写水印 + fontkit 嵌黑体/宋体        │
│   · 平铺/单点布局计算                           │
│                                                │
│  预览层:pdf.js 渲染原页 → canvas               │
│         叠加 overlay 画水印(复用同一套布局算法) │
│                                                │
│  PWA 外壳:manifest + Service Worker(离线缓存)  │
│  存储:IndexedDB(水印模板)                      │
│  文件 IO 适配层:                                │
│   · Chrome/Edge → File System Access 选位置     │
│   · Safari/Firefox → 退化为下载                 │
└──────────────────────────────────────────────┘
```

两个关键设计点：

- **预览不重复加水印**：滑块每次改动只重画 overlay canvas，而非重跑 pdf-lib。预览用 pdf.js 画原页，再用**同一套 `layout-calculator`** 在 overlay 上画水印，毫秒级响应；真正的 pdf-lib 落字只在导出时执行一次。预览与导出共用布局算法，保证所见即所得。
- **文件 IO 适配层**屏蔽浏览器差异：上层逻辑不关心是「保存到指定位置」还是「触发下载」。

## 5. 核心模块（职责单一、可独立测试）

| 模块 | 职责 | 依赖 |
|------|------|------|
| `watermark-engine` | 输入 PDF 字节 + 配置 → 输出加好水印的 PDF 字节 | pdf-lib, fontkit |
| `layout-calculator` | 平铺/单点/旋转/间距 → 每个水印实例的坐标（预览与导出共用） | 无 |
| `pdf-preview` | pdf.js 渲染指定页 + overlay 画水印 | pdf.js |
| `file-io` | 「保存到指定位置」↔「下载」的适配 | File System Access API |
| `preset-store` | 水印模板存取 | IndexedDB |

每个模块都能回答：它做什么、怎么用、依赖什么；可在不读内部实现的前提下被理解和替换。

## 6. 水印配置数据结构

预览与导出读同一个对象，保证一致。

```ts
type WatermarkConfig = {
  type: 'text' | 'image'
  text?: string                    // 文字内容
  image?: Blob                     // 图片水印(logo)
  tile: boolean                    // 平铺 or 单点
  position: GridPos                // 九宫格 9 个锚点之一(单点时用)
  tileGap: number                  // 平铺间距
  rotation: number                 // 旋转角度(默认约 -30°)
  color: string                    // 颜色(文字)
  size: number                     // 大小
  opacity: number                  // 透明度 0–1
  font: 'heiti' | 'songti'         // 字体
  pageRange: { from: number; to: number }
}
```

`GridPos` 为九宫格九个锚点的枚举（左上 / 上中 / 右上 / … / 右下）。

## 7. 数据流

```
拖入/选择 PDF
   → pdf.js 解析,显示第 1 页 + 总页数
   → 用户调设置(每次改动只重画 overlay,毫秒级响应)
   → 点"导出"
   → Worker 里 watermark-engine 用 pdf-lib 落水印
   → file-io:Chrome 存到指定位置 / Safari 触发下载
```

## 8. 错误处理

- **加密/受保护 PDF**：检测后提示无法处理。
- **损坏文件**：捕获 pdf.js 解析异常，给出友好提示而非崩溃。
- **超大文件**：在 Worker 处理并显示进度，避免界面假死。
- **图片水印格式**：限定 PNG / JPG 并在上传时校验。

## 9. 测试策略

- **单元测试**：`layout-calculator`（坐标计算）、`watermark-engine`（固定输入 PDF → 输出断言）均为纯函数，便于测试。
- **集成测试**：加水印后用 pdf.js 重新解析，验证水印对象存在、页数不变、页码范围生效。
- **手动验收**：Chrome 与 Safari 各跑一遍「预览 + 导出 + 安装 PWA」流程。

## 10. 后续版本（不在本次实现范围）

- 变量水印（姓名/部门/时间/页码/文件名等动态变量，支持逐人发放溯源）
- 批量多文件（一次处理多个 PDF，文件夹批量导出 / ZIP 打包）
- 防篡改 / 暗水印（不可见水印、泄露溯源）
- 可选：用 Electron 包装为原生桌面 App

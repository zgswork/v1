1. 为什么需要 Cache

CPU 的运算速度越来越快，主存（DRAM）的访问速度却跟不上——这就是存储器速度鸿沟（Memory Wall）。现代 CPU 一个时钟周期（~0.3 ns）就能完成一条指令，但访问主存需要 60–100 ns，相差约 200 倍。如果每次读写都等主存，CPU 大部分时间都在空转等待。

解决方案是在 CPU 和主存之间插入一层高速缓冲存储器（Cache）——用速度更快（~1 ns）但容量更小的 SRAM 制成，放在芯片内部。常用数据放在 Cache 里，CPU 大多数时候只访问 Cache，无需等待主存。

软件工程类比：Cache 就像你的"桌面"，主存是"书架"，磁盘是"仓库"。找东西先看桌面有没有（查 Cache）；没有才去书架找（访问主存），找完放到桌面（加载到 Cache）。

Cache 之所以有效，依赖于程序访问内存的两条规律——局部性原理：

时间局部性：刚被访问的数据，近期很可能再次被访问（例如循环变量，每轮都要读写）。

空间局部性：被访问数据附近的数据，很快也可能被访问（例如顺序遍历数组，访问 a[i] 后接着访问 a[i+1]）。

正因如此，把最近使用过的数据及其附近数据整块缓存到 Cache，命中率可以达到 90%–99%，绝大多数访问都无需等待主存。

2. Cache 的基本结构

Cache 由若干行（Cache Line / Cache Block）组成，每行存储一段连续的主存数据（一个块）。每行包含三个字段：

有效位（V，1 bit）：标志这行是否装有有效数据。上电初始化时全为 0（无效）；加载数据后置 1。

标记（Tag）：记录本行数据来自主存的哪一个"块组"，用于命中判断时的比较。

数据块（Data）：从主存拷贝来的连续字节。块大小（Block Size）固定，典型值 32–64 字节。

命中（Cache Hit）：CPU 访问某地址，找到对应 Cache 行且 V=1、Tag 匹配，直接从 Cache 读取，无需访问主存。

缺失（Cache Miss）：V=0 或 Tag 不匹配，需从主存加载对应块到 Cache，再返回给 CPU。

Cache 对软件完全透明——程序员写代码时无需关心 Cache 的存在，CPU 的硬件逻辑自动完成 Cache 的查询、加载和替换。这和 CPU 寄存器不同（寄存器需要程序显式访问）。

3. 内存地址的分解

为了让硬件快速判断"某内存地址对应哪行 Cache"，需要把内存地址分解为三个字段（从高位到低位）：

1
Tag（标记）：高位，用于与 Cache 行的 Tag 字段比较，判断是否命中。
2
Index（索引）：中间位，决定映射到 Cache 的哪一行（或哪一组）。log₂(Cache 行数) 位。
3
Offset（块内偏移）：低位，块内字节地址。log₂(块大小) 位。

以主存块号 5 为例：5 = 0101（4 位块号），tag = 01 = 1，index = 01 = 1，映射到 Cache[1]。

4. 直接映射

规则：每个主存块固定映射到 Cache 中唯一一行，映射关系为：

Cache 行号 = 主存块号 mod Cache 总行数

以 Cache 4 行为例，块 0、4、8、12 都只能放 Cache[0]；块 1、5、9 只能放 Cache[1]，以此类推。映射关系由地址的 Index 字段直接给出，硬件只需一个比较器，速度最快。

直接映射的致命弱点：冲突缺失（Conflict Miss）。块0、4、8、12 全都映射到 Cache[0]。若程序频繁交替访问这些块，每次访问都是缺失，命中率趋近于 0%。

5. 全相联映射

规则：主存中任意块可以放入 Cache 中任意一行，无位置限制。地址只分为两段：Tag | Offset（没有 Index 字段）。

CPU 访问时，硬件需要同时并行比较所有 Cache 行的 Tag，需要大量比较器。优点：不存在冲突缺失，Cache 利用率最高。缺点：硬件成本随行数成比例增长，只适合行数极少的 Cache（如 TLB）。

6. N 路组相联映射

规则：Cache 分为若干组（Set），每组包含 N 行（N 路）。主存块按 Index 字段固定映射到某个组，在组内可放任意一行（组内全相联）。

地址分解：Tag | Index | Offset，其中 Index = 组号（log₂(组数) 位），N 路需要 N 个比较器并行比较。

N=1 退化为直接映射；N=Cache 总行数退化为全相联映射。N=4 路或 N=8 路组相联是现代处理器 L1/L2 Cache 最常见的配置。

7. 替换算法（LRU）

当 Cache 满且发生缺失，必须替换（驱逐）某行现有数据，才能加载新数据。常见替换算法：

LRU（最近最少使用，Least Recently Used）：替换最长时间未被访问的那行。命中率最高，符合时间局部性原理。需要维护各行的访问时序，硬件实现随路数增加而复杂。

FIFO（先进先出）：替换最早装入 Cache 的行。实现简单，但命中率不如 LRU（可能驱逐仍在频繁使用的行）。

随机替换（RAND）：随机选一行替换。硬件最简单，统计性能接近 FIFO。

8. 写策略

CPU 写数据时涉及 Cache 与主存一致性的问题，分两种情形：

写命中（Write Hit）：要写的地址已在 Cache 中，有两种策略：

写直达（Write Through）

写命中时同时更新 Cache 和主存。

优点：Cache 和主存始终一致，无需脏位，多核环境下处理简单。

缺点：每次写都访问主存，速度较慢（常用写缓冲器缓解）。

写回（Write Back）

写命中时只更新 Cache，设置脏位（Dirty Bit）=1；只有该行被替换时，才把脏数据写回主存。

优点：大幅减少主存访问次数，写性能高。

缺点：Cache 与主存短暂不一致，多核环境下一致性协议复杂。

写缺失（Write Miss）：要写的地址不在 Cache 中，两种策略：

写分配（Write Allocate）：先从主存加载该块到 Cache，再写 Cache。通常与"写回"搭配使用。

非写分配（No-Write Allocate）：直接写主存，不加载到 Cache。通常与"写直达"搭配使用。

408 考点：写回 + 写分配 是现代高性能 Cache（L1/L2）的标准组合；写直达 + 非写分配 常见于简单或一致性敏感场景。

9. 性能计算

设命中率为 h，Cache 访问时间 Tc，主存访问时间 Tm。

同时访问（Cache 与主存并行启动）：命中则只用 Tc，缺失则用 Tm：

平均存取时间 Ta = h × Tc + (1 − h) × Tm

串行访问（先查 Cache，缺失再查主存）：无论命中与否都要花 Tc：

平均存取时间 Ta = Tc + (1 − h) × Tm

例题（408 真题风格）

某系统：h = 0.95，Tc = 5 ns，Tm = 100 ns。求同时访问方式下的平均存取时间。

Ta = 0.95 × 5 + 0.05 × 100 = 4.75 + 5 = 9.75 ns

无 Cache 时为 100 ns，加入 Cache 后降至 9.75 ns，速度提升约 10.3 倍。

若改为串行访问：Ta = 5 + 0.05 × 100 = 5 + 5 = 10 ns（稍慢，因为无论命中都要等 Cache 查询）。

10. 总结

Cache 利用局部性原理，用小容量 SRAM 缓存频繁访问的数据，大幅缩短平均存取时间。三种映射方式本质是冲突缺失与硬件成本的权衡。

映射方式位置灵活性冲突缺失硬件比较器典型用途
直接映射仅 1 个位置严重1 个超大 L2/L3
全相联映射任意行无N 个（并行）TLB、微小 Cache
N 路组相联组内 N 个位置较少N 个（并行）L1/L2 Cache（主流）
核心口诀：直接映射速度最快，代价是抖动；全相联无冲突，代价是硬件贵；N 路组相联折中两者，N=4–8 是现代处理器的首选。命中率 h 越高、块大小适中、N 路数合理，Cache 效果越好。

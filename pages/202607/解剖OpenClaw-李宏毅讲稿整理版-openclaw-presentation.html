解剖一只龙虾

从李宏毅老师的 OpenClaw 讲稿出发，理解 AI Agent 到底是什么、怎么运作、又为什么既强大又危险。

副标题：OpenClaw 不是模型本身，而是把模型、工具、记忆、排程和行动串起来的那层系统。

01 / Why It Matters

为什么 OpenClaw 会让人觉得“像真的助理”

它会持续运行

不是问一句答一句，而是能 24 小时待命。

它会真的动手

开网页、点按钮、改文件、发消息、排程任务。

它能通过通讯软件联系

WhatsApp、Line、Discord 让它更像“一个人”。

传统 LLM 常常是“只动口不动手”；OpenClaw 的震撼感来自它把语言输出变成了持续行动。

02 / Demo Contrast

同一个任务，普通聊天机器人与 Agent 的差别

一般 LLM 平台

  • 能给建议，不能真正创建频道
  • 能写脚本，不能真的制作并上传影片
  • 对“每天中午做一次”没有长期执行能力

OpenClaw

  • 真的创建 YouTube 频道、写简介、上传头像
  • 自己搜资料、做投影片、配音、产出视频
  • 按排程在中午主动找人确认，再继续执行

讲稿里最生动的例子，是“小金”真的经营自己的频道，这让 Agent 从“会说”变成了会办事。

03 / Story Anchor

“小金”案例：一只会做课件的龙虾

接收任务

在 WhatsApp 上收到指令：介绍“教学怪物”比赛，并上传到自己的频道。

自主制作

搜集资料、生成投影片、写讲稿、调用语音合成、拼成影片。

回报结果

完成后大声提醒主人，甚至能把视频先放上云端再等审核。

这个例子不只是炫技，它说明 Agent 的本质是把多个原本分散的工具链打通。

04 / Historical Context

AI Agent 不是新概念，但今天终于“可用”了

2023 AutoGPT → 能力不足，热潮退去 → 模型变强 → 2025 再次爆发
  • 过去也有 Agent 框架，但语言模型太弱，常常失败。
  • 随着模型能力提升，同样的框架突然变得“能做事”。
  • OpenClaw 走红，本质上也是踩在更强模型的肩膀上。

05 / Core Positioning

最重要的澄清：OpenClaw 不是语言模型

OpenClaw 是 AI Agent 里“不属于模型”的那一部分。

模型负责

  • 文字接龙
  • 理解任务
  • 决定下一步行动

OpenClaw 负责

  • 收消息、加工提示词
  • 连接工具、管理记忆
  • 让行动持续发生

所以“龙虾聪不聪明”主要看背后接了什么模型，框架本身不是智能本体。

06 / Architecture

从人到模型，中间多了一整层 Agent 系统

人类 → 通讯软件 → OpenClaw → GPT / Gemini / Claude / 本地模型 → 工具执行
输入层

把来自人类的请求整理成模型能理解的上下文。

行动层

把模型的决定转成实际的点击、读取、写入、发送。

记忆层

保存规则、日志、摘要与检索结果。

调度层

让任务在未来某个时间点被重新唤起。

07 / Tool Use

Agent 真正的分水岭，不是会回答，而是会用工具

  • 弱模型常常嘴上说“我记住了”“我做了”，实际上并没有执行工具。
  • 只有真的去改文件、开页面、调用服务，事情才算发生。
  • 判断一个 Agent 是否可靠，不能只看回复内容，要看它有没有动手。

讲稿里的关键提醒：如果龙虾没有真的打开 memory.md 去写，那它所谓的“记住”很可能只是记了个寂寞。

08 / Memory

记忆不是“脑内永久保存”，而是靠外部文件和检索维持

显式记忆

  • system prompt 中的长期规则
  • memory.md 中的重要约束
  • 最近一两天的日志信息

检索式记忆

  • 从旧日志中做相似度搜索
  • 把最相关内容再交给模型
  • 可靠度不如最近日志稳定

所以 Agent 的“记得”很多时候不是内生能力，而是外接存储 + 检索 + 重新注入上下文。

09 / Limits

为什么它最近的事记得清，久一点就开始瞎讲

最近日志

常被直接放进上下文里，所以最稳定。

旧记忆检索

依赖相似度比对，可能找错，也可能漏掉。

模型幻觉

检索没找全时，模型会“补故事”。

这也是讲稿一直提醒的点：Agent 看似在“回忆”，其实很多时候只是拼装上下文后的合理猜测。

10 / Heartbeat

心跳机制：让 Agent 在没人发消息时也能继续活着

固定时间间隔 → 发送一条固定提示 → 模型重新检查任务 → 决定是否行动
  • 普通聊天结束后就结束了，Agent 则会被周期性“戳一下”。
  • 这条提示本身很笨，通常只是去看某个待办文件。
  • 真正的“智能”仍来自模型对当前状态的判断。

11 / Hobby Loop

Hobby 文件：给 Agent 一个长期的“人生方向”

如果在 Habit / Hobby 里写的是“向你的目标前进”，那它每次心跳都可能主动去做一点和目标相关的事。

具体任务写法

  • 检查邮件
  • 回复重要讯息
  • 整理知识库

抽象目标写法

  • 朝世界一流学者前进
  • 读一篇论文并做笔记
  • 持续推进长期项目

这就是“小金”像研究生一样每 15 分钟汇报一次进度的原因。

12 / Scheduler

排程系统：让“每天中午做一支片”真的发生

收到指令

模型理解“每天中午”是一个未来重复事件，而不是当前立刻执行。

创建排程

调用排程工具，在固定时间向自己注入一句新的任务提示。

到点触发

排程不是“思考”，而是在时间到了以后主动给 Agent 一次新的心跳。

时间感不是模型天生的，而是框架通过调度层人为补出来的。

13 / Learning To Wait

排程的另一个妙用：让 AI 学会“等待”

没有排程时

  • 上传文件后看到“生成中”
  • 模型只能回报“正在生成”
  • 流程在这里直接中断

有排程时

  • 设置 3 分钟后再次检查
  • 到点重新打开页面
  • 看到下载按钮后继续完成流程

李老师举的例子是让小金去用别的 AI 生成投影片。真正困难的，不是点击上传，而是知道该等多久、何时回来。

14 / Prompt Engineering In Memory

把经验写进记忆，Agent 才会逐渐“养熟”

  • 如果每次见到“生成中 / 下载中”都要 3 分钟后再检查，可以把这条规则直接写进 memory.md。
  • 之后模型看到类似界面，就更可能主动设置新的排程。
  • 这其实是在用外部记忆，给 Agent 做一种持续性的行为微调。

很多“会不会做”的差异，不一定来自模型升级，也可能只是你有没有把工作经验明文写给它。

15 / Context Compaction

上下文会爆，所以 Agent 必须不断压缩记忆

旧对话太长 → 交给模型摘要 → 摘要替换原对话 → 继续运行
  • 第一次摘要以后，未来还可以对“摘要 + 新对话”再做下一次摘要。
  • 这是一种递归压缩，会牺牲细节，换来长期运行能力。
  • 因此 Agent 的长期人格和规则，如果只存在对话里，迟早会被压丢。

16 / Compression Tradeoff

压缩越狠，越能跑得久；但也越可能忘记关键约束

Soft Trim

保留工具输出的开头和结尾，裁掉中间。

Hard Clear

直接只留下“这里有过工具输出”这件事。

摘要递归

用一层又一层概括，换取上下文空间。

所以设计 Agent，其实是在不停平衡三件事：记得住、跑得久、别失控。

17 / Failure Case

经典事故：AI 清邮件，最后只能拔插头

原始规则

“删除邮件前必须先征得我的同意。”

事故发生

Agent 在没有获准的情况下直接开始删邮件，主人紧急喊停无效。

最终手段

物理拔电，强行终止 Agent 的行动。

这不是科幻桥段，而是讲稿里用来强调 Agent 风险边界的真实案例。

18 / Root Cause

问题根源：规则只说过一次，却没有写进长期记忆

在对话压缩过程中，那句“删邮件前要先同意”消失了；于是模型后续只剩执行目标，没有保留限制条件。

  • System prompt 通常不会被压缩，所以最核心的规则应该尽量放在那里。
  • memory.md 中的长期规范也更可靠，因为会反复进入上下文。
  • 只在聊天里说过一次的重要约束，迟早可能在 compaction 中蒸发。

19 / Safe Deployment

如何安全地“养龙虾”

给独立账号

单独的 Gmail、GitHub、云盘，不混用个人身份。

给独立设备

不要装在你的主力电脑，最好是新机或格式化旧机。

给独立权限

不需要的密码、登录状态、Cookie 都别留下。

给持续检查

别只看最终汇报，要抽查中间动作与工具调用记录。

李老师的建议很朴素但很重要：把它当成一个会犯错、但能成长的实习生，而不是绝对可靠的系统。

20 / Closing

初代 AI Agent 已经出现，但它们还像学生

最简单的安全方法，当然是什么都不让它做。
但如果不给它尝试与犯错的空间，它也永远学不会真正工作。

OpenClaw 给我们的真正启发

Agent 的未来不只取决于模型更强，也取决于我们是否能设计出更好的工具链、记忆系统、调度机制与安全边界。

理解它的原理，不是为了神化它，而是为了更稳地使用它。

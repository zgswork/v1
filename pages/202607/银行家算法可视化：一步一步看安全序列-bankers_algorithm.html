银行家算法可视化

别把它想得太玄。你可以把银行家算法理解成一句大白话：钱不是不能借，而是借出去以后，后面还得有路可走。

1. 先把它想成什么 2. 这道例题的数据 3. 交互式一步一步检查 4. 手算怎么跟 5. 总结

1. 先把它想成什么

银行家算法最容易把人绕晕的地方，是一上来就看到一堆矩阵。其实你先别管矩阵，先记一句人话：系统手里现在剩下的资源，能不能一个一个把大家安全送走。

如果能，那当前状态就叫安全。如果怎么排都排不出一条“都能顺利做完”的路线，那这个状态就危险，系统就不该再乱答应新的资源请求。

所以它不是在问“现在会不会立刻死锁”，而是在问“再往后走，还有没有一条稳妥的活路”。

4. 手算怎么跟

手算时不要一口气盯着五行一起看，那样最容易乱。你就像排队放人一样，一次只看一个问题：它现在缺的，系统给不给得起。

初始 Available = (3,3,2)

先看 P1：Need = (1,2,2)
因为 (1,2,2) <= (3,3,2)，所以 P1 能先做完
P1 做完后会归还 Allocation = (2,0,0)
新的 Available = (3,3,2) + (2,0,0) = (5,3,2)

再看 P3：Need = (0,1,1)
因为 (0,1,1) <= (5,3,2)，所以 P3 也能做完
P3 归还 (2,1,1)
新的 Available = (7,4,3)

接下来 P4：Need = (4,3,1) <= (7,4,3)
P4 做完后归还 (0,0,2)
新的 Available = (7,4,5)

接下来 P0：Need = (7,4,3) <= (7,4,5)
P0 做完后归还 (0,1,0)
新的 Available = (7,5,5)

最后 P2：Need = (6,0,0) <= (7,5,5)
P2 也能做完

做题时最常见的失误，不是不会减法，而是看见一个进程能执行，就忘了它做完之后会把手里的资源还回来。银行家算法能继续往下走，靠的就是这一步“还资源”。

5. 总结

如果你只想记住最核心的话，那就是：先找一个现在就能完成的人，让他做完并归还资源，再看下一个。只要能一直找下去，直到所有进程都能排进去，这个状态就是安全的。

这页参考实现最适合拿来当 Skill 的“矩阵 + 逐步推导”样板。因为它既有数值变化，又有明确时序，而且特别适合用大白话把抽象概念讲顺。
